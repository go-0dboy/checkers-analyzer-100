# СтоКлетка — анализатор международных шашек

Доска 10×10, правила FMJD, дерево партии с вариантами, комментариями и NAG,
импорт/экспорт FEN и PDN, локальная база партий и Android через Capacitor 8.

## Запуск и проверки

Требуются Node.js 22.18+ и npm. Зависимости закреплены в `package-lock.json`. `npm audit --omit=dev` проверяет зависимости приложения; CLI и браузерные тесты находятся в devDependencies.

```bash
npm ci
npm run dev                  # http://localhost:3000
npm run format:check         # форматирование проверяемых модулей и тестов
npm run check                # TypeScript, регрессионные тесты, production web build
npx playwright install chromium
npm run test:e2e             # настоящий браузер, Scan WASM, навигация, отмена
npm run benchmark:search -- --baseline d3b1fd8  # сравнение встроенного поиска
```

Встроенный движок: alpha-beta, итеративное углубление, обязательный поиск взятий,
полные окна для кандидатов, ограниченная TT с контекстом ничьей и нормализацией
расстояния до выигрыша. Поиск работает в Worker. При отмене Worker останавливается,
а Promise запроса завершается. При недоступности Worker работает запасной поиск
в основном потоке; на медленном устройстве он может ухудшать отзывчивость.
При слишком малом времени возвращается легальный запасной ход без подтверждённой оценки.
Дебютная рекомендация не заменяет оценку позиции и явно помечается как книга.

История партии учитывается для троекратного повторения и правил 25/16/5 ходов.
Правила: [FMJD Annex 1, разделы 4 и 6](https://www.fmjd.org/downloads/news/948/Annex%201%20official%20FMJD%20rules%20of%20international%20draughts.pdf).
При загрузке отдельного FEN история до него неизвестна: счётчики начинаются с нуля.
Если у стороны нет легальных ходов, проигрыш имеет приоритет над ничьёй.

Полный маршрут взятия хранится в дереве, протоколе Worker и PDN.
При совпадающих начальном и конечном полях доска предлагает выбор маршрута.
Неполная PDN-запись с разными наборами взятых фигур отвергается как неоднозначная.
Некорректный импорт не заменяет текущую партию.

Файл PDN с несколькими партиями открывает список выбора; партии не склеиваются.
Каждую выбранную партию можно отдельно сохранить в базу. Во вкладке «Ходы» можно
указать результат партии; он попадёт в PDN и локальное сохранение.
Общий предел импорта, редактора и хранения: 500 полуходов в каждой линии,
9999 узлов ходов на дерево. Превышение отклоняется с сообщением.
При повреждённом автосохранении исходная запись не перезаписывается: интерфейс
предлагает скачать JSON для восстановления и явно начать новую партию.

Комментарии и NAG не перезапускают анализ. Позиции уже посещённых узлов кешируются;
изменения комментариев сохраняются через 300 мс, а при скрытии страницы или выходе
сбрасываются сразу. Ходы и навигация сохраняются сразу. Ошибки автосохранения,
базы и копирования показываются в интерфейсе. Авария анализа предлагает повтор;
после ошибки Worker повтор может использовать запасной поиск в основном потоке.

**Настоящая база окончаний не подключена.** Материальная подсказка приблизительна
и не доказывает выигрыша или ничьей.

## Scan 3.1 WASM

В `public/scan/` включена рабочая сборка Scan 3.1 с pattern-весами. Адаптер использует
Hub v2 через экспорт `scan_command`, проверяет `ready`, сохраняет `info`/PV и
проверяет полный ответ на легальность. Запуск и анализ происходят в отдельном Worker.
При отсутствии файлов, ошибке или таймауте используется встроенный движок.
Путь к ресурсам учитывает Vite `BASE_URL`. Сеть для анализа не нужна.
Scan загружается только при включённой настройке и необходимости анализа.
Worker встроенного движка также создаётся только по запросу.
«Человеческий стиль» поддерживает только встроенный движок; при включённом Scan
этот переключатель недоступен с пояснением.

Воспроизводимая пересборка — Emscripten **4.0.20**:

```bash
# Активируйте emsdk 4.0.20 перед запуском.
bash scripts/build-scan.sh
# Только при желании использовать более слабую PST-оценку:
SCAN_PST_ONLY=1 bash scripts/build-scan.sh
```

Версии исходников, SHA-256 весов и команды сборки закреплены в скрипте.
Подробности и лицензия: [public/scan/README.md](public/scan/README.md).
Scan не использует базы окончаний в этой сборке. Сила приложения отдельно не измерена.

Нейросеть и обучение исключены из релиза. Анализ выполняют Scan и встроенный движок.
Сохранённые ранее партии и обычные настройки совместимы; старые веса не загружаются.
Результаты ревью, замеры и ограничения: [CODE_REVIEW.md](CODE_REVIEW.md).

## Android APK

Требуются **JDK 21**, Python 3, Android SDK 36 (`ANDROID_HOME`), build-tools 36.0.0.

```bash
npm ci
bash scripts/build-apk.sh                # debug
bash scripts/build-apk.sh --release      # подписанный release
```

Для release нужны все четыре переменные:
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`. Скрипт не выпускает неподписанный APK под видом signed release.
Временный keystore удаляется после сборки; его содержимое не печатается.
Версия APK берётся из `package.json`; в CI versionCode — `GITHUB_RUN_NUMBER`.

Иконки из `assets/app-icon.svg` применяются к web и Android, включая adaptive icon.
Сгенерированный каталог `android/` не хранится в git.

GitHub Actions запускает проверки и браузерные тесты, затем собирает debug APK
на push любой ветки или PR. APK доступен в артефакте `app-debug`.
Тег `v*` дополнительно запускает подписанную release-сборку и GitHub Release.
Если секретов подписи нет, release-job явно завершается ошибкой; debug остаётся доступен.
Не публикуйте release-тег до настройки секретов.

## Структура

- `src/engine/core.ts` — правила, полная идентичность ходов, FEN.
- `src/engine/draw.ts` — повторения и счётчики ничейных окончаний.
- `src/engine/search.ts`, `impl.ts`, `client.ts` — встроенный поиск и Worker.
- `src/engine/scan*.ts` — Hub-протокол, клиент и Worker Scan.
- `src/engine/pdn.ts`, `src/state/tree.ts` — PDN и дерево партии.
- `src/state/useGame.ts`, `db.ts` — состояние, автосохранение и IndexedDB.
- `tests/` — регрессионные и браузерные проверки.
